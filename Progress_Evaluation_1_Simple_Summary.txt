2. WHAT HAS BEEN DONE

A. Problem and dataset understanding

- The project predicts the nightly price of an Airbnb listing.
- The target is log_price, which is the natural logarithm of the price in US dollars.
- This is a supervised regression problem because the output is a number.
- The main intended user is an Airbnb host who wants help choosing a suitable price.
- The dataset contains 74,111 rows and 29 original columns.
- The dataset is described as the Airbnb Price Dataset from Rana on Kaggle.

B. Exploratory Data Analysis (01_EDA_Airbnb.ipynb)

- The structure of the dataset and the meaning of the columns were studied.
- Numeric, categorical, Boolean, date, text, identifier, and target columns were identified.
- Incorrect stored data types were found, such as percentages and true/false values stored as text.
- Missing values were counted and studied. Twelve columns contain missing values.
- The largest amounts of missing data are in host response rate, review score, first review, last review, thumbnail URL, and neighbourhood.
- The reasons for some missing values were investigated. For example, review information is usually missing because a listing has no reviews.
- Exact duplicates, duplicate IDs, and near-duplicates were checked. No duplicate listing rows were found.
- Invalid or suspicious values were checked. Two listings had impossible prices below $10, 198 rows had zero bathrooms, and four rows had zero beds.
- The target distribution was studied. Normal price is very skewed, but log_price is much more balanced and is better for modelling.
- Numeric feature distributions and outliers were studied.
- Categorical and Boolean feature distributions were studied.
- Relationships between the input features and price were studied.
- Important findings include:
  - The number of guests a listing can accommodate is a strong price factor.
  - Room type is the strongest categorical price factor.
  - Neighbourhood and city are important.
  - Distance from the city centre is useful in most cities.
  - Amenities contain useful information but require cleaning.
- Possible data leakage was identified. Review history is not available for a new listing, and learned preprocessing must use training data only.
- A final EDA summary connects each finding to a preprocessing or modelling decision.

C. Data preprocessing and feature engineering (02_Preprocessing_Airbnb.ipynb and src/preprocessing.py)

- Six unsuitable columns were removed from modelling: id, name, description, thumbnail_url, zipcode, and host_has_profile_pic.
- The two listings with prices below $10 were removed, leaving 74,109 valid rows.
- Zero bathrooms and zero beds were changed to missing values so they can be imputed.
- Text percentages, true/false values, dates, and amenities were converted into useful formats.
- New features were created, including:
  - guests per bedroom
  - beds per guest
  - guests per bathroom
  - studio indicator
  - real-bed indicator
  - amenity count and cleaned amenity list
  - distance from the city centre
  - host tenure
  - listing age
  - days since the last review
  - review and missing-value indicators
- Neighbourhood names were combined with city names to avoid mixing places with the same name in different cities.
- The valid data was split into 80% training data and 20% test data.
- The split was stratified by price groups and uses random_state 42, so every group member can reproduce the same split.
- All learned preprocessing is fitted on the training data only.
- Missing neighbourhoods are filled using nearby training listings. Other numeric values use the training median, and categorical or Boolean values use suitable training-based rules.
- Outliers are kept because many represent real large properties. Extreme numeric values are capped only for linear models.
- Low-cardinality categories use one-hot encoding.
- Rare property types are grouped as Other.
- Neighbourhood uses smoothed, cross-fitted target encoding.
- Amenities use multi-hot encoding, keeping common amenities.
- Numeric features are scaled for linear models but not for tree models.
- Near-constant and highly correlated features are removed where appropriate.
- Separate preprocessing pipelines were prepared for linear models and tree models.
- Separate listing-only and full feature sets were prepared. The listing-only set is suitable for a new-host prediction system because it does not need later review history.
- A leakage checklist and a numerical leakage example are included.
- The cleaned train/test files, fixed split IDs, fitted preprocessors, and feature-name lists were saved for later modelling.
- The notebooks contain saved outputs and no recorded error cells were found during this review.

6. SHORT VIVA EXPLANATION

Our project predicts an Airbnb listing's nightly price. We used a public Airbnb dataset with 74,111 rows and 29 columns. The target is log_price, so the task is regression. During EDA, we studied data types, missing values, duplicates, invalid values, outliers, distributions, and the relationships between listing details and price. We found that room type, capacity, location, and amenities are important. We also found two impossible prices and some invalid zero values.

For preprocessing, we removed unsuitable columns and the two invalid price rows. We cleaned data types, handled missing values, encoded categories and amenities, created useful features such as guests per bathroom and distance from the city centre, and selected useful features. We split the data into training and test sets before fitting any learned preprocessing. This prevents information from the test set from leaking into training. We prepared different pipelines for linear and tree models and saved the processed data for the next stage.
